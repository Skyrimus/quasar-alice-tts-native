# Quasar Alice TTS

**Неофициальный экспериментальный TTS-клиент для локального запуска на Яндекс Станции.**

Quasar Alice TTS — независимая реализация клиента, который отправляет запрос на синтез речи через внутренний протокол UniProxy и воспроизводит полученное аудио непосредственно на колонке через ALSA. Программа написана на C++ и не использует исходный код или библиотеки Яндекса.

> [!IMPORTANT]
> Проект не разработан, не одобрен и не поддерживается Яндексом. Он использует **недокументированный интерфейс**, совместимость с которым не гарантируется. Возможность вызвать функцию с помощью штатного приложения «Дом с Алисой» **не означает разрешения** вызывать её через внутренний API. Используйте проект только на принадлежащем вам устройстве, с собственной учётной записью и с учётом применимых условий сервисов.

## Возможности

- Генерация речи из заданного текста с помощью серверного TTS Алисы.
- Локальное воспроизведение результата через ALSA (PCM, 48 кГц, 16 бит, моно или стерео).
- Приём аудиопотока Opus, в том числе в контейнере Ogg.
- Использование штатного локального хранилища авторизации **той же Станции**, на которой запускается программа.
- Выбор учётной записи из хранилища, ALSA-устройства и внутреннего идентификатора голоса.
- Режимы проверки содержимого хранилища (`--inspect`) и WebSocket-соединения (`--probe`).

Клиент **не выполняет офлайн-синтез**: для генерации речи требуется связь с серверами Яндекса. В текущем виде он воспроизводит аудио, но не сохраняет его в WAV/MP3-файл.

## Принцип работы

1. Читает локальный файл `/data/quasar/account_storage.dat` и использует токен авторизации вашего аккаунта из его бинарной структуры.
2. Получает UUID той же колонки из `/data/quasar/quasar_metricad.json`.
3. Устанавливает TLS/WebSocket-соединение с UniProxy, используя штатные учётные данные устройства.
4. Отправляет запрос `TTS/Generate` с текстом и параметрами синтеза.
5. Декодирует полученный Opus-поток и воспроизводит PCM через ALSA.

В текущей реализации используется **access-токен** вашего аккаунта Яндекс, код определяет наличие refresh-токена в хранилище, но **не выполняет обновление токенов**.

## Требования

- Собственная Яндекс Станция с доступом к Linux-окружению, в котором запускается программа.
- Доступ на чтение штатных файлов авторизации и UUID устройства.
- Доступное устройство воспроизведения ALSA и подключение к интернету.
- Для сборки: компилятор с поддержкой C++17, OpenSSL, ALSA (`libasound`) и `libopus`; удобнее использовать `pkg-config`.

Получение root-доступа, модификация прошивки и экспорт учётных данных **за пределы устройства** не входят в состав проекта. Сам клиент считывает токен из локального хранилища для авторизации запросов. Перед изменением ПО устройства самостоятельно оцените технические риски и применимые условия лицензии.

## Использование

Команды ниже рассчитаны на запуск **непосредственно на собственной Станции**, где доступны штатные файлы устройства.

Проверить, найдено ли локальное хранилище и присутствуют ли записи авторизации (значения токенов не выводятся):

```bash
./quasar_tts --inspect
```

Проверить установление TLS/WebSocket-соединения:

```bash
./quasar_tts --probe
```

> `--probe` проверяет WebSocket-handshake, но **не гарантирует**, что сервер принял авторизацию или что TTS-запрос выполнится успешно.

Произнести текст через динамики колонки:

```bash
./quasar_tts --text "Привет! Это проверка синтеза речи."
```

Указать параметры явно:

```bash
./quasar_tts \
    --text "Проверка воспроизведения" \
    --voice shitova.us \
    --alsa default \
    --channels 2 \
    --timeout 30
```

### Параметры командной строки

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| `--text TEXT` | Текст для синтеза | Обязателен, кроме `--inspect` и `--probe` |
| `--voice NAME` | Внутренний идентификатор голоса | `shitova.us` |
| `--alsa NAME` | Устройство вывода ALSA | `default` |
| `--channels 1\|2` | Число выходных аудиоканалов | `2` |
| `--timeout SECONDS` | Общий тайм-аут операции (1–120 секунд) | `30` |
| `--storage FILE` | Путь к файлу хранилища авторизации | `/data/quasar/account_storage.dat` |
| `--account N` | Номер записи аккаунта, начиная с 1 | `1` |
| `--uuid VALUE` | UUID устройства | Читается из файла |
| `--uuid-file FILE` | Файл с UUID (текст или JSON с полем `UUID`) | `/data/quasar/quasar_metricad.json` |
| `--ca-file PEM` | Пользовательский набор доверенных CA-сертификатов | CA-файл колонки, если доступен; иначе системный |
| `--inspect` | Локальная проверка хранилища авторизации | Выключен |
| `--probe` | Проверка WebSocket-handshake | Выключен |
| `--help`, `-h` | Справка | — |

Максимальная длина аргумента `--text` в текущем коде — **32 768 байт** (не символов Unicode).

## Безопасность учётных данных

- **Не публикуйте** `account_storage.dat`, access/refresh-токены, cookie, дампы разделов устройства и другие секреты. Не добавляйте их в Git, issue, логи или CI.
- Используйте только авторизацию своей колонки и своего аккаунта. Не просите других пользователей передавать вам файлы авторизации.
- Программа предназначена для локального исполнения: она считывает токен с устройства и передаёт его серверу Яндекса по TLS. При этом сам токен является чувствительным секретом.
- Не отключайте проверку TLS-сертификатов и не используйте проект для обхода ограничений доступа, лимитов или тарификации.
- При подозрении на раскрытие токена прекратите его использование и воспользуйтесь доступными средствами отзыва/перепривязки авторизации.
